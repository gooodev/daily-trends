# trends 収集ガイダンス

`collect` が使う、構造化しづらい方針・数値の正本。興味領域（コア/上昇中/監視中/収集抑制）と収集ソースの一覧は Cloudflare D1 に移行済みで、`https://daily-trends-interests-api.gooodev.workers.dev/` から取得する（`collect/SKILL.md` の手順 0 を参照）。このファイルにはそちらに乗らないプロース中心の方針だけを置く。

## 収集上限

サイトは「週ごと・大分類タブごと」に記事を日付降順で並べて表示する（`site/src/lib/trends.ts` の `TAB_ORDER`）。各タブが 1 日 5 件程度になるよう、大分類ごとの上限を設ける。掲載時は興味度の高い記事を優先し、上限を超える分は低興味度の記事から削る。

- AIツール: 5 件
- AIモデル: 5 件
- AI倫理: 5 件
- Security: 5 件（分析記事優先、単発 CVE 速報は簡潔に）
- 開発: 5 件
- キャリア・組織: 5 件
- その他（専門外含む）: 0〜2 件

上記はあくまで目安。当日話題が薄い大分類は無理に埋めない（興味度の低い記事で水増ししない）。

## カテゴリ（大分類 / 小分類）

`category` は必ず `大分類/小分類` の形式で書く。大分類はサイトのヘッダーのタブになるため、**以下の固定リストから選ぶ**（表記も完全一致させる。リストに無い大分類を作らない）。小分類は記事の上に小見出しとして表示される自由記述で、当日の記事に合わせて中粒度で切る。

| 大分類 | 対象 | 小分類の例 |
| --- | --- | --- |
| `AIツール` | コーディングエージェント・AI 開発ツール・エージェント実装・AI の業務活用事例 | `エージェント開発・実装`, `コーディングツール`, `業務活用` |
| `AIモデル` | LLM・ローカル LLM・オープンモデル・ベンチマーク・論文・研究 | `ローカルLLM`, `オープンモデル`, `論文・研究` |
| `AI倫理` | AI の安全性・規制・プライバシー・著作権・ガバナンス・企業導入方針・雇用への影響 | `安全性`, `規制・法律`, `ガバナンス・企業導入` |
| `Security` | 脆弱性・インシデント・サプライチェーン攻撃・AI を使った攻撃 | `脆弱性・インシデント`, `サプライチェーン`, `AI×攻撃` |
| `開発` | JS/TS・データスタック・インフラ・アーキテクチャ・開発ツール（AI 以外） | `JS・TS`, `データスタック`, `インフラ・ツール` |
| `キャリア・組織` | キャリア・働き方・組織論・チームづくり | 小分類なし（`キャリア・組織` のみ）でも可 |
| `その他` | 上記に当てはまらない話題 | 小分類なし（`その他` のみ）でも可 |

- AI に関わる記事でも、主題がセキュリティ事案なら `Security`、AI を使わない開発の話なら `開発` に入れる
- 同じ記事が複数の大分類にまたがる場合は、主題に最も近い 1 つに入れる
- `Security` は「単発 CVE 速報」と「大規模インシデント・サプライチェーン攻撃の分析」が混在しがち。単発 CVE 速報は簡潔に留め、分析記事（背景・影響範囲・対応指針が書かれているもの）を優先して拾う
